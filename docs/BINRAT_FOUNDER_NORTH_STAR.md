# BINRAT — FOUNDER NORTH STAR AND EXECUTION CONTRACT

**Founder-confirmed direction:** 2026-10-11. **Status:** product/agent orchestration authority; **not** runtime, legal, token, deployment, signing, or capability-status authority.
**Canonical question:** **"Can the user employ a Rat, leave, and come back to useful, source-backed work?"**

## 1. Do not lose the plot

> **BINRAT is a bounded workforce of specialized Rats that investigate crypto for the user, exchange evidence through typed handoffs, remember what they find, and return when something matters.**

**YOU CAN'T WATCH ALL THIS SHIT. YOUR RATS CAN.**

- The launch scanner is **Rat Zero's eyes / an entry point**, not the entire product.
- Deployer recurrence, transaction hashes, digest counts, index coverage and RPC health are **supporting facts**, not user-value headlines by themselves.
- Product loop: **FIND → EMPLOY → LEAVE → RETURN**.
- Forensic loop: **SNIFF → REMEMBER → INVESTIGATE → WATCH → ALERT**.
- The user asks in plain chat or from a Case; a Rat accepts an explicit task; the system records limits and handoffs; the user returns to an understandable finding or honest non-finding.
- The first screen answers **WHAT HAPPENED → WHY CARE → WHAT CAN I DO?**. Raw receipts remain accessible, not in the headline.
- Do not manufacture financial FOMO. The meaningful tension is **"what relevant evidence would I otherwise miss?"**, not "buy now."

**North-star demonstration:** a real user assigns an investigation, leaves, a bounded Rat actually works or watches without intervention, and a genuinely new verified finding returns them to the exact Case. Then prove **one genuine cross-specialist handoff** on real evidence. Offline synthetic replay and mock delivery do **not** satisfy these gates.

## 2. Frozen crew and collaboration model

| Surface | Role | Public status direction / truth boundary |
|---|---|---|
| **Rat Zero / Scout** | Find supported fresh Pons launches, open Cases, inspect retained evidence | **LIVE** only where real production evidence verifies it |
| **Tripwire / Watcher** | Durable declared Watch, quiet when nothing happens, alert on qualifying future event | **BUILDING**; owner-only candidate != public live |
| **Sniffer / Trail Hunter** | Follow verified funder → recipient → history → possible later Pons launch, hand evidence to Rat Zero | **PROVING**; prediction/real autonomous yield unproven |
| **Den / Organize** | Job ledger: worker, subject, scope, budgets, state, progress, finding, cancel, return | **PLANNED/POST-LAUNCH**; local prototype != production |
| **Working Rat** | Bounded additional persistent labor/capacity gated by verified active stake, when implemented | **PLANNED/inactive**, even if vault staking exists |
| **Two unnamed Rats** | Future specialists | **LOCKED**, no invented ETA, capability or entitlement |

Rats **collaborate through typed, source-linked handoffs under one origin job**. A handoff carries subject, tool/skill authority, evidence refs, chronology and *remaining* budget; it cannot expand permissions or reset the budget. There is **no free-form multi-agent chatter**, model self-modification, arbitrary tool loading, open-ended web crawling, chain trading, signing or custody in V1. Any provider model is a hypothesis, not factual authority. Rat personality is a presentation layer. Receipts decide claims.

**Working definition of one employed Rat:** a real admitted and persisted task; an explicit owner/subject/trigger, tool policy, dollar/call/time ceiling, cancellation, observable outcome/stop reason and real return path. A decorative character, watch-shaped button, local scripted replay or green unit test is insufficient.

## 3. Separate three gates — never confuse them

**A. Public evidence foundation (largely real):** fresh Pons V2 launches on Robinhood Chain 4663, source-bound Cases and partial history. The live source/version and freshness must still be checked at the time of claim.

**B. Workforce-product MVP (not yet proven live):** **one end-to-end real, persistent and cancelable owner job** using existing infrastructure: Case/chat → employ → leave → verified later event or explicit honest quiet/unknown → Telegram/Web return → exact Case. A true **multi-Rat MVP** adds **one** real, bounded Sniffer → Rat Zero → Tripwire or equivalent typed handoff; it is not accomplished by separate demos.

**C. $BINRAT token transaction:** separate exact-manifest, legal/compliance, independent upstream, wallet/economics, rehearsal, signing and public-fact gates. The selected planning rail is Pons V2 / Robinhood 4663 / native ETH / PonsVault Staking, with 0% creator tax, zero opening/dev buy, no private presale, no hidden allocation. **The full autonomous workforce is not a prerequisite to the token transaction**. Equally, **do not claim employment, paid capacity, active staking entitlement or prediction is live unless the actual runtime proves it**. Working Rat remains inactive until wallet/principal binding, threshold and capacity enforcement are proven. Stake buys labor, **never better truth**. Bounded fiat-credit jobs are a potential future alternative, not a launched offering.

Never let a local branch, PR, roadmap or planning document silently promote BUILDING/PROVING to LIVE. Capability and token state come from deployed, verified manifests/receipts and exact launch gates, not this file.

## 4. Product delivery priority — strict order

1. **Preserve and stabilize Rat Zero → Case → receipts**. Do not mistake this for the final workforce.
2. **One real persistent owner Rat job** with clear save/reopen/cancel/return, measured authority and verified delivery (existing Tripwire is the nearest candidate). If a genuine later event has not occurred, say **NO_EVENT_YET**, not failure or success.
3. **One real typed specialist-to-specialist handoff**, only after a viable source and useful outcome are demonstrated. Reuse #123/#128 contracts, #132/#133 local job/Den proofs; these are scaffolding, not live competence.
4. **User-friendly Den and paid capacity** after actual jobs exist. Don't build a job-management dashboard before there are jobs.
5. Additional Rats, general A2A/MCP mesh, arbitrary web agents, AI-driven claims, speculative historical-outcome collectors and trading all remain out of MVP.

Separate parallel **token launch compliance/mechanics track** remains gated independently; don't re-open token economics in workforce tasks.

## 5. Kill criteria: stop work, not the vision

| Workstream / trigger | Decision |
|---|---|
| Finding offers only a number, address match, receipt jargon or unknown outcome; user has no clear next investigation | **KILL THE HOOK**, not the memory subsystem. Real J1.5 result: **0/8 actionable Cases**; don't feature recurrence as "alpha". |
| Lifecycle hypothesis cannot access the canonical historical state within its registered budget | **DEFER THAT SOURCE PATH**. Four-token test: **0/4 verified** after **32/32 reads**; access-blocked, not disproven. No infinite provider hunt. |
| Provider challenges/authorization failures, stale provenance, impossible chain reads | **BLOCK / FAIL CLOSED**. No bypass or guessed alternate RPC. One bounded diagnostic/correction, then return an authorization or availability decision. |
| Candidate needs stale, mixed or production-bound D1/webhook to pretend to work | **BLOCK THE RELEASE**, preserve production. |
| Real Rat job cannot persist, respect boundaries or return its exact Case | **MVP NOT MET**; don't upgrade the label from engineering proof. |
| Real specialist output fails evidence, chronology, adversarial or competent-baseline checks | **NO SPECIALIST PROMOTION**; preserve experiments and fall back to deterministic tools. |
| Same hypothesis has failed **two distinct bounded attempts** without new evidence | **PARK IT**; owner must explicitly reopen with a new falsifiable fact and ceiling. |
| A proposed task cannot name its user-facing decision/consequence and stopping condition | **REJECT TASK BEFORE IMPLEMENTATION**. |
| A feature creates uncapped cost, signing/capital authority or facts unsupported by sources | **KILL OR REDESIGN**; no local "temporary" exemption. |

**DO NOT declare the whole BINRAT vision dead** merely because an RPC provider, one history signal, a benchmark or an alert candidate is blocked. Conversely don't keep investing because many tests or PRs exist; sunk cost is not user value.

## 6. Retry, exploration and spend budgets (agent policy, not runtime config)

Every agent task must declare before work: **hypothesis, product consequence, baseline evidence, source authority, exact max steps/calls, monetary cap, deadline or wall-clock bound, success/kill gate, allowed changes, and stop authority**.

**Default when not explicitly authorized otherwise:**
- **0 paid RPC/model calls; $0 new spend; 0 chain transactions; 0 live messages; 0 production mutations.**
- **One scoped task, one changeset, one targeted test pass, ONE hostile review, fix Critical/High only, ONE targeted rereview if needed, STOP.** Do not loop review rounds or fix Low/Medium solely to feel finished.
- **One bounded root-cause diagnosis and one targeted repair attempt per blocker.** If the same blocker persists, **BLOCKED**; don't escalate to a new provider, collector, framework or migration.
- **At most two predeclared experiments per hypothesis**; second requires a reason the evidence should differ. No opportunistic sample enlargement or changing the denominator after a negative result.
- **One transient transport retry maximum** only if idempotence, cost and explicit caps are proven. **Zero retries** for authentication failures, managed challenges, mutation ambiguity, spent budgets, signing/broadcast, or uncertain external delivery. Preserve unknown states.
- **No parallel provider fan-out, self-spawning subagents or recursive handoffs** without a frozen and enforced job budget. Handoffs share, never reset, the origin budget.
- **On exhaustion: output evidence + verdict + one next recommendation + STOP.** No background work, repeated smoke tests or new follow-on phases without owner consent.

**Illustrative experiment ceilings from already closed experiments are historical facts, not permission to reuse their spend:** J1 latest 20 sample; J1.5 eight Cases; four-token lifecycle probe 32 reads. Existing Tripwire code has its **own enforced limits**; verify actual runtime values instead of copying examples into configuration.

**No invented estimates:** if a provider or environment cannot expose reliable usage/cost, report **COST_UNKNOWN** and stop before enabling any paid recurring job. Any positive monetary ceiling or new resource provisioning requires an explicit owner-scoped grant. Existing billing limits are not new spending authority.

# BINRAT rebuild roadmap — gated planning to launch readiness

**Status:** planning only. These gates do not approve code modifications in competing branches, merges, production deploys, token actions, API spend, payment collection or public-live claims. Pons-first priorities supersede old Arc-first design habits; preserve existing Arc source and resolve older dual-chain launch commitments before making public parity claims.

## Acceptance rubric for *every* proposed frontend PR

1. **Traceability:** reference owner-approved Figma frame, story/fixture ID and exact source data contract; state which prior decision it implements. No random redesign or silently resurrected CSS.
2. **Function:** primary CTA actually works, navigation/back works, interaction states persist correctly, user can reach source receipts and understand failures.
3. **Visual:** approved screenshots at 320, 360, 390, 430 CSS px and selected desktop/intermediate widths; actual browser evidence, not only an AI textual assurance. No clipping/overlap, unintended horizontal scroll or mascot obscuring action.
4. **Usability/accessibility:** keyboard and focus behavior, adequate contrast and touch targets, reduced motion, correct content hierarchy and semantic controls. Automated axe/Playwright checks plus manual/owner design judgment.
5. **Truth:** DEMO is conspicuous; unknown/partial/stale/provider error and supported live variants tested; role/phase/source and source timestamps visible; no raw data/derivation mismatch. Long token names, sparse cohorts and unrecognized quote assets handled.
6. **Coherence:** default to approved primitives, component specimens and navigation. New pattern needs a brief *goal, tried reuse, alternative, rationale, screenshot and review*. Heuristic exceptions allowed, not hidden inconsistency.
7. **Performance:** no unnecessary all-page canvas/chart/graph bundles; verify low-powered/mobile loading, bounded animations and network calls; objective budget set after fixture prototype and measured baseline.
8. **Bounded execution:** PLAN→CHANGESET→VERIFY→VERDICT; implement/test; exactly one independent hostile review; repair material Critical/High; one targeted rereview and close; no automatic merge/deploy.

**Screenshots regression pass ≠ good original art direction.** Owner must separately approve the initial G2 design; screenshot CI later prevents silent drift. If two autonomous reviewers disagree on taste, owner-approved reference and specific user task govern, not endless agent rework.

## Completion versus deferred work

The smallest user-visible first release can demonstrate genuine Pons launch discovery, receipt-linked investigation, a basic funding detective and honest unknowns **if verified operationally**. Do not wait for unlimited funding hops, every V4 pool, proprietary AI narratives or perfect trade prediction. Conversely, do not call a full-featured thermometer operational until mature full-phase histories are proven. Existing 10K-DAU synthetic goals are **research targets**, not current performance or release claims. Token issue/marketing/legal/security gates are independent of this web-product roadmap.

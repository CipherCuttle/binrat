## Authority and conflict rules

This pack preserves **approved strategic direction**, not a final palette, design file, all proposed library selections, product pricing, or implementation/deployment authority. Owner corrections supersede historical notes; add dated entries to the ledger before changing a previously accepted choice.

**Pons V2 / Robinhood Chain 4663 first.** Existing Arc evidence is preserved, but the new frontend is not Arc-first. Older repository research proposed dual-chain launch coverage; reconcile that separately, never silently assume it was implemented or that earlier owner's latest Pons-first priority is reversed.

The owner explicitly rejected the previous bento/G2/North Star frontend and permanent visual style rules. PR #31 merged into a **stacked parent feature branch**, not necessarily `main`, and removed old visual authority. No old screenshot, component, design token or mockup is approved for reuse. **Only the original owner-approved pixel-art rat is an authoritative mascot asset.** Verify the master asset's actual current path before design or image work.

PR #40 established three independently verified Pons `TokenLaunched` receipts in a narrow source-verification scope, **not** funding intelligence, full curve/V4 pricing or live indexing. PR #39 is a separately reviewed offline prepaid quota candidate, not live billing. All PR states and heads must be refreshed at execution time.

The unchanging principle: **the rat makes investigation delightful; receipts determine what's true.** Five-second understanding, roughly thirty-second investigation and a clear next action are experience targets, not measured guarantees.

## Change protocol

Each significant later decision requires a ledger entry: dated owner decision or new experimental result, prior state, new state, rationale, dependencies, superseded entry and operational authority (normally none). Coding agents must read the ledger before turning a proposal into a permanent rule.

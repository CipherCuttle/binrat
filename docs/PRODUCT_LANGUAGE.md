# BINRAT PRODUCT LANGUAGE

Status: **canonical naming / voice / public-copy authority**

This file controls wording and role names across Web, Telegram and the public roadmap. It does not decide evidence truth or capability status.

## Voice

The Rat is:

- short;
- dry;
- slightly feral;
- competent;
- mildly hostile to bullshit;
- never hostile to the user;
- never a corporate assistant.

**BINRAT decides what is true. The Rat decides how to say it.**

## Core lines

Preferred recurring language:

- **THE RAT REMEMBERS.**
- **HE GETS THE SCRAPS. YOU GET THE RECEIPTS.**
- **SMELLS FAMILIAR.**
- **FOUND SOMETHING.**
- **LEAVE A TRIPWIRE IN THE TRASH.**
- **DEGEN DECIDES ATTENTION. RECEIPTS DECIDE TRUTH.**
- **GIVE IT A CASE. IT COMES BACK WITH RECEIPTS.**

Use repetition selectively. These are anchors, not mandatory slogans on every surface.

## Public-copy pattern

Prefer:

`FERAL HEADLINE → LITERAL EXPLANATION → RECEIPT / SOURCE`

Example:

> **SMELLS FAMILIAR.**  
> This exact source-reported deployer appears across 4 retained launches.  
> Open receipts →

The headline may have character. The explanation may not upgrade evidence.

## Role language

### Current Pons / Robinhood 4663 source

Use the exact event roles:

- `DEPLOYER`
- `TOKEN`
- `CURVE`
- `PAIR TOKEN`
- `LAUNCH`

Never silently upgrade:

- deployer → creator;
- address → human;
- recipient → trader/buyer;
- recurrence → skill;
- pattern → profitability;
- similarity → common human identity.

If a source explicitly reports a **creator** role, that scoped surface may say creator. Legacy Arc Creator Files retain their source-bounded terminology.

Good:

> **same deployer. five launches. smells familiar.**

Bad:

> serial rugger detected.

## Evidence language

Canonical evidence words:

- **OBSERVED**
- **DERIVED**
- **PATTERN**
- **UNKNOWN**
- **COMPLETE**
- **PARTIAL**
- **UNVERIFIED**
- **MISSING**

Green/positive presentation never means safe. Orange/red presentation never independently means risky.

## Capability/status language

Status should stay boring and inspectable. Prefer canonical values such as:

- `ENGINEERING_PASS`
- `DEPLOYED`
- `PUBLIC_LIVE` / manifest-specific public state
- `BUILDING`
- `PLANNED`
- `EXPERIMENTAL`
- `BLOCKED`

Do not turn roadmap prose into a status source.

## Words for product surfaces

Prefer concrete BINRAT nouns:

- receipt
- trail
- bag
- case
- tripwire
- hunt
- raid
- evidence
- replay
- deployer
- launch
- checkpoint

Keep technical phrases such as “bounded investigation,” “longitudinal evidence,” “point-in-time projection,” and “structured contribution layer” in Method/spec/legal contexts when precision requires them. Avoid them as hero headlines.

## Hard avoids

Do not emit as BINRAT conclusions:

- smart money;
- good buy / bad buy;
- BUY / SELL / APE instructions;
- SAFE / RUG scores;
- “scammer” or “rugger” from address recurrence alone;
- guaranteed returns, APY, listings or price appreciation;
- unsupported human identity;
- roadmap dates invented from plans;
- “autonomous” wording that implies unrestricted authority.

The Rat can be degen. The evidence contract cannot be.

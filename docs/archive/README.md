# BINRAT archive

Status: **HISTORICAL / NON-AUTHORITATIVE**

Nothing under `docs/archive/` is current global product, roadmap, language, rail, deployment or launch authority.

Current authority starts at `docs/README.md`.

## Why these files exist

These documents preserve previous plans, reviews, acceptance receipts and superseded product directions so decisions remain auditable without polluting normal model context.

Archived material may contain statements that were true, proposed or accepted at the time but conflict with current BINRAT direction.

Examples include:

- ArcPad / Arc 5042 as the primary product rail;
- Arc creator-centric product language;
- old frontend/fixture architecture;
- old roadmap chapter names such as INVESTIGATE / CONNECT;
- rejected or superseded roadmap visual plans.

## Rule

Do not “repair” an archived document to match current reality.

If current truth changes, update the canonical authority instead. History stays historical.

## Collections

- `legacy-arc-product/` — ArcPad-era PRD, implementation, frontend and presentation contracts.
- `roadmap-precanonical/` — roadmap and Living Scenes planning material superseded by `docs/ROADMAP.md`.
- `legacy-design/` — superseded visual-system / asset-production plans.
- `legacy-arc-launch/` — dated Arc launch-mechanics/configuration narrative and hostile-review material.
- `receipts-2026-09/` — dated deployment/acceptance receipts retained for provenance.

Historical links inside archived files may reference their original repository paths. Use Git history if an exact old tree is required.

Some frozen legacy gate artifacts still name original root paths. Where required, those root paths are compatibility pointers only; the historical bytes live here.

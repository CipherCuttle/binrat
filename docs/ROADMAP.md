## 01 — SNIFF · LIVE

### RAT ZERO FINDS THE FRESH TRASH.

**Rat:** RAT ZERO / SCOUT  
**User value:** Fresh Pons launches become inspectable Cases instead of another stream of tickers.

Rat Zero:

- catches supported fresh Pons launches;
- opens the evidence;
- checks what BINRAT already remembers;
- exposes receipts and visible gaps.

Public CTA:

> **START DIGGING**

This is the immediate value surface.

## 02 — REMEMBER · LIVE

### THE RAT REMEMBERS.

**Rat:** BINRAT memory / Rat Zero  
**User value:** Sites change, wallets recur, narratives get rewritten. The retained trail stays inspectable.

REMEMBER includes the supported memory system around:

- Cases;
- receipts;
- deployer recurrence;
- Trash Trails;
- point-in-time replay;
- retained evidence and explicit missing coverage.

Public anchor:

> **HE GETS THE SCRAPS. YOU GET THE RECEIPTS.**

Memory is the durable moat. Prediction never replaces it as evidence authority.

## 03 — WATCH · BUILDING

### LEAVE A TRIPWIRE IN THE TRASH.

**Rat:** TRIPWIRE / WATCHER  
**User value:** Define something worth watching, leave, and only come back when a supported change qualifies.

Tripwire direction:

- exact watched subject;
- declared trigger;
- bounded lifetime/work limit;
- durable state;
- quiet success when nothing happens;
- alert with a direct return to the changed Case.

Current public truth:

> Existing Watch/alert rails have verified pieces. Persistent workforce-style Tripwire jobs remain **BUILDING**.

Do not render a fake working job row before durable admission exists.

## 04 — HUNT · PROVING

### SNIFFER FOLLOWS THE MONEY.

**Rat:** SNIFFER / TRAIL HUNTER  
**User value:** Follow an evidenced funder into new recipients and preserve the trail before a later launch rewrites the story.

Sniffer direction:

`funder → recipient → bounded history → handoff → strictly later Pons launch`

Current public truth:

- real prospective funding has been detected;
- a real funding-to-recipient handoff has been saved;
- later-launch yield / predictive usefulness is not yet proven;
- public production Sniffer jobs are not live.

Therefore the status is:

> **PROVING**

Allowed copy:

> **Real funding handoffs captured. Later-launch prediction is still being proven.**

Never say “predicts launches” until evidence actually supports it.

## 05 — ORGANIZE · BUILDING

### PUT YOUR RATS TO WORK.

**Surface:** THE DEN + WORKING RAT  
**User value:** One place to see which Rats are out, what they were asked to do, what they found, and why they stopped.

The Den should eventually show one row per user-facing job:

- Rat;
- subject;
- assignment;
- state;
- last meaningful activity;
- work/time limit;
- delivery connection;
- finding / Case;
- stop action.

Launch V1 token convergence:

> **FREE RAT DIGS WHEN YOU ASK.**  
> **WORKING RAT KEEPS DIGGING AFTER YOU LEAVE.**

Active $BINRAT stake unlocks bounded additional labor/capacity when implemented and verified.

Permanent boundary:

> **STAKE BUYS LABOR. NOT TRUTH.**

A bigger stake never changes the factual rules of a Case.

## 06 — AUTONOMOUS RAT · LOCKED

### GIVE IT A CASE. COME BACK TO RECEIPTS.

**Status:** LOCKED as a broad public promise.

The direction is a bounded specialist workforce that can:

- accept a typed job;
- use a sealed capability/tool profile;
- hand work between specialists under the origin job;
- retain receipts;
- stop on budgets/deadlines;
- return supported findings.

Automation is not evidence authority.

No unrestricted agent, trading authority, wallet authority, or invisible swarm is implied.

## Cross-cutting product loop

`FIND → EMPLOY → LEAVE → RETURN`

Under the hood:

`SNIFF → REMEMBER → INVESTIGATE → WATCH → ALERT`

The first is the user journey.  
The second is the forensic method.

## Crew status vocabulary

For customer-facing crew cards:

- **LIVE** — a user can use this capability now on the stated public surface.
- **BUILDING** — active implementation exists, but the promised user job is not yet fully available.
- **PROVING** — bounded real-world evidence exists, but usefulness/competence is not yet sufficient for a public production claim.
- **LOCKED** — future slot; identity/capability intentionally not promised.

These are presentation labels. Technical deployment/authorization remains governed by the capability manifest and launch receipts.

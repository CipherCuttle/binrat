# BINRAT Brand V1 — Copy Library

**Status:** reusable public/social copy system  
**Authority:** `docs/PRODUCT_LANGUAGE.md`, `docs/PHILOSOPHY.md`, Brand V1  
**Rule:** this library does not create product truth, capability truth, identity truth, financial advice, or roadmap status.

## Operating contract

Every public line must survive this test:

**FERAL HEADLINE → LITERAL EXPLANATION → RECEIPT / SOURCE**

The Rat may compress attention. It may not compress away uncertainty.

Canonical evidence words remain:

- **OBSERVED**
- **DERIVED**
- **PATTERN**
- **UNKNOWN**
- **COMPLETE**
- **PARTIAL**
- **UNVERIFIED**
- **MISSING**

Canonical role language remains source-bounded. Never silently upgrade:

- deployer → creator;
- address → human;
- recipient → trader/buyer;
- recurrence → skill;
- pattern → profitability;
- similarity → common human identity.

For live/generated copy, values in braces are data slots, not sample facts.

## 1. RECEIPT posts

**Structural formula:** short feral finding → one literal observation → evidence state + source → one action.  
**Max recommended length:** headline 4 words; literal line 160 characters; full post/card body ~320 characters before metadata.  
**Evidence boundary:** one retained finding only. State exactly what was observed or derived and expose source/coverage. Do not turn recurrence, similarity, or visual prominence into a verdict.  
**Forbidden:** “smart money,” “rugger,” “safe,” “good buy,” “alpha,” “this wallet knows,” unsupported creator/human identity, hidden PARTIAL/MISSING coverage.

Examples:

1. **SMELLS FAMILIAR.**  
   This exact source-reported deployer appears across {launch_count} retained launches.  
   **PATTERN · {coverage}** · Open receipts →

2. **THE RAT KEPT THIS.**  
   {artifact_type} was observed for {launch_id} at {observed_at}.  
   **OBSERVED · {coverage}** · Source →

3. **SAME SCRAP. NEW BAG.**  
   The same {field_name} value appears in {match_count} indexed launches.  
   **PATTERN · {coverage}** · Compare receipts →

4. **FOUND A RECEIPT.**  
   BINRAT retained the launch-time {artifact_type} before the current change.  
   **OBSERVED · {coverage}** · View snapshot →

5. **THIS ONE REPEATS.**  
   {observable_name} matches {match_count} earlier retained observations.  
   **DERIVED · {coverage}** · Inspect matches →

6. **NOTED. BAGGED.**  
   The source reported deployer {address_short} for launch {launch_id}.  
   **OBSERVED · {coverage}** · Open receipt →

## 2. CASE FILE posts

**Structural formula:** case headline → literal case summary → 2–4 high-value facts → explicit claim boundary → source/action.  
**Max recommended length:** headline 5 words; narrative 220 characters; 4 fact rows maximum on share cards.  
**Evidence boundary:** compress an investigation without inventing connective tissue. Related observations may be a PATTERN; they are not automatically one actor, one intent, or one outcome.  
**Forbidden:** “case closed” when evidence is partial, criminal/scam labels from recurrence, creator attribution not supplied by source, outcome claims without outcome coverage.

Examples:

1. **SAME DEPLOYER. FIVE LAUNCHES.**  
   This source-reported deployer recurs across {launch_count} retained launches. Outcomes are shown only where covered.  
   **PATTERN · NOT A VERDICT** · Open Case File →

2. **THE TRAIL IS LONGER.**  
   This launch connects to {related_count} earlier receipts through {relationship_type}.  
   **DERIVED · {coverage}** · Follow Trash Trail →

3. **THREE RECEIPTS. ONE CASE.**  
   BINRAT grouped {receipt_count} source-backed observations for this launch.  
   **{coverage}** · Inspect evidence →

4. **THE STORY CHANGED.**  
   A retained launch-time artifact differs from the currently observed version.  
   **OBSERVED · {coverage}** · Compare snapshots →

5. **WE HAVE PART OF IT.**  
   The case contains {known_count} supported findings; {missing_count} requested evidence areas remain unavailable.  
   **PARTIAL** · See gaps →

6. **GIVE IT A CASE.**  
   BINRAT traced the available history for {case_subject} and kept each supporting receipt separate.  
   **{coverage}** · Open Case File →

## 3. RAT FOUND SOMETHING posts

**Structural formula:** 1–3 word character headline → immediate literal finding → one evidence strip → one action.  
**Max recommended length:** headline 3 words; explanation 150 characters; one evidence strip only.  
**Evidence boundary:** this is the most expressive format, so the literal line must immediately identify exactly what was found. “Something” may be a receipt, recurrence, difference, missing source, or other bounded observation—not “a gem.”  
**Forbidden:** “alpha found,” “ape this,” “winner,” “next 100x,” “caught a scammer,” suspense that withholds the literal finding.

Examples:

1. **FOUND SOMETHING.**  
   This exact deployer appears in {launch_count} retained launches.  
   **PATTERN · {coverage}** · Open trail →

2. **SMELLS FAMILIAR.**  
   {observable_name} matches an earlier retained observation.  
   **DERIVED · {coverage}** · Compare →

3. **RAT GOT PAPER.**  
   A launch-time {artifact_type} is retained for this case.  
   **OBSERVED · {coverage}** · See receipt →

4. **TRASH MOVED.**  
   The current {artifact_type} differs from the retained launch-time version.  
   **OBSERVED · {coverage}** · Replay →

5. **HOLE IN THE BAG.**  
   {evidence_area} could not be verified from the available source.  
   **MISSING** · See coverage →

6. **SAME TRACKS.**  
   {match_count} launches share the same observed {field_name}.  
   **PATTERN · {coverage}** · Inspect matches →

## 4. X launch / feature announcements

**Structural formula:** canonical product noun + feral hook → what the feature literally does → current status/availability → one action.  
**Max recommended length:** target ≤240 characters before link; hard cap 280 including link/metadata.  
**Evidence boundary:** announce only capability states supported by the canonical manifest/deployment evidence. “Shipped” must mean available in the stated surface, not merely ENGINEERING_PASS.  
**Forbidden:** fake launch dates, “revolutionary blockchain intelligence,” “AI-powered alpha,” “fully autonomous” without scoped authority, “live” for non-public capability.

Examples:

1. **TRASH TRAILS ARE OPEN.**  
   Follow a launch back through retained deployer history and source-backed receipts. Coverage stays visible.  
   Open BINRAT →

   Try Replay →

   More history fits in one case without turning patterns into verdicts.  
   Open a case →

5. **THE RAT REMEMBERS MORE.**  
   BINRAT now retains {new_artifact_type} as a source-attributed receipt where coverage exists.  
   Read the update →

6. **NEW BAG: {feature_name}.**  
   {literal_feature_description}. Status: **{capability_status}**.  
   Details →

## 5. X replies

**Structural formula:** answer first → evidence qualifier → source/action only if useful.  
**Max recommended length:** 180 characters preferred; 250 maximum.  
**Evidence boundary:** replies must be at least as careful as cards. Correct overclaims rather than matching the user’s certainty.  
**Forbidden:** dunking on the user, pretending UNKNOWN is negative evidence, price calls, “yes this is a scam,” unsupported identity, coy non-answers.

Examples:

1. “Same deployer, yes. Same human, not established. We have {launch_count} retained launches tied to the source-reported deployer.”

2. “We can show the recurrence. We can’t turn recurrence into skill or intent.”

3. “Coverage is **PARTIAL** here. The missing rows are missing evidence, not a clean bill of health.”

4. “That receipt is **OBSERVED** from {source_name}. The relationship shown above it is **DERIVED**.”

5. “No supported match in the indexed coverage we have. That is not the same as ‘never happened.’”

6. “The Rat found a pattern, not a verdict. Open the receipts and decide what deserves attention.”

7. “We don’t score SAFE/RUG. We show what was observed, what was derived, and what is still unknown.”

## 8. Telegram empty states

**Structural formula:** plain empty result → scope qualifier → next useful action.  
**Max recommended length:** 180 characters.  
**Evidence boundary:** distinguish “none in this scope” from “none exists.” Empty state must name index/filter/coverage limits when relevant.  
**Forbidden:** “clean,” “safe,” “nothing suspicious,” “all good,” “no history” unless the system truly searched complete supported history.

Examples:

1. **NO RECEIPTS IN THIS BAG.**

4. **CASE FILE EMPTY.**  
   No retained evidence is available for this subject yet.

5. **NOTHING TO REPLAY HERE.**  
   No eligible point-in-time receipts exist for the selected checkpoint.

6. **THE BAG IS EMPTY.**  
   Your current filters removed every retained result. Clear filters →

## 9. Telegram errors

**Structural formula:** what failed → what remains safe/intact → retry/next action.  
**Max recommended length:** 220 characters.  
**Evidence boundary:** errors must never be converted into evidence states. A failed source query means unknown/unavailable, not negative evidence.  
**Forbidden:** fake blame, “source says no,” swallowing partial failure, anthropomorphic claims that imply the Rat verified something it did not.

Examples:

1. **RAT DROPPED THE BAG.**  
   The source request failed. No new evidence was recorded from this attempt.  
   Retry →

2. **CAN’T OPEN THAT RECEIPT.**  
   The stored reference is unavailable right now. Existing case data is unchanged.

3. **SOURCE DIDN’T ANSWER.**  
   This evidence area remains **UNKNOWN** for this attempt.  
   Retry →

4. **WATCH NOT CHANGED.**  
   BINRAT could not confirm the update, so the previous Watch state remains in place.

5. **CASE LOAD FAILED.**  
   We could not retrieve the case bundle. Nothing has been reclassified.  
   Retry →

6. **REPLAY STOPPED.**  
   The checkpoint could not be reconstructed from available receipts.  
   Evidence state remains unchanged.

## 13. “We found nothing” states

**Structural formula:** exact search result → searched scope → coverage caveat → optional next action.  
**Max recommended length:** 220 characters.  
**Evidence boundary:** “no match found” is a query result, never evidence of safety, uniqueness, or absence outside the indexed scope.  
**Forbidden:** “clean,” “safe,” “legit,” “nothing wrong,” “first ever,” “unique” unless complete evidence specifically proves the narrower claim.

Examples:

1. **NO MATCH FOUND.**  
   Nothing matched {query_condition} in the currently indexed coverage.

2. **RAT CAME BACK EMPTY.**  
   No supported recurrence was found in this search scope. That does not prove none exists elsewhere.

3. **NO RECEIPT FOR THAT.**  
   BINRAT does not currently have source-backed evidence for {claim_or_artifact}.

4. **NOT IN THIS BAG.**  
   The requested artifact is absent from the retained case bundle. Coverage: **{coverage}**.

5. **NO ELIGIBLE HISTORY.**  
   The selected replay window contains no retained observations that satisfy the checkpoint rules.

6. **NOTHING VERIFIED.**  
   Available sources did not establish the requested claim. State: **UNVERIFIED**.

## 14. Partial / unknown evidence states

**Structural formula:** state word first or early → what is known → what is not known → why/next source if available.  
**Max recommended length:** 260 characters.  
**Evidence boundary:** UNKNOWN, PARTIAL, UNVERIFIED, and MISSING are distinct. Do not collapse them into one vague “insufficient data” bucket when the product knows which applies.  
**Forbidden:** color-coded insinuation, treating missing data as favorable, filling gaps with model inference, “probably.”

Examples:

1. **PARTIAL.**  
   BINRAT has {known_count} supported receipts for this case; {missing_area} is outside current coverage.

2. **UNKNOWN.**  
   The available evidence does not establish {question}. No stronger claim is warranted.

3. **UNVERIFIED.**  
   {claim} is present as a claim, but BINRAT does not currently have supporting evidence sufficient to verify it.

4. **MISSING.**  
   The expected {artifact_type} is not available in the retained evidence bundle.

5. **PARTIAL OUTCOME COVERAGE.**  
   Outcomes are available for {covered_count} of {total_count} retained launches. Do not generalize across the uncovered rows.

6. **KNOWN HERE. UNKNOWN THERE.**  
   {fact_a} is **OBSERVED**. {fact_b} remains **UNKNOWN**. Keep them separate.

## 15. Source / coverage disclaimers

**Structural formula:** source attribution → coverage scope → inference limit.  
**Max recommended length:** 180 characters for card footer; 300 characters for expanded tooltip.  
**Evidence boundary:** disclaimers must be specific enough to stop the likely overread. They are not legal fog and should not contradict the headline.  
**Forbidden:** tiny-print reversal of an overclaim, generic “DYOR” as substitute for boundaries, “not financial advice” attached to an actual buy/sell instruction.

Examples:

1. “Source-reported deployer. Address identity beyond that role is **UNKNOWN**.”

2. “Coverage: **PARTIAL**. Counts apply only to retained launches in the indexed scope.”

3. “Relationship: **DERIVED** from matching observed fields. Common human identity is not established.”

4. “Outcome coverage is incomplete. Uncovered launches are not treated as positive or negative outcomes.”

5. “No match was found in current coverage. This does not prove global absence.”

6. “Point-in-time replay excludes observations recorded after {checkpoint}.”

7. “Source unavailable on this attempt. Evidence state remains **UNKNOWN** rather than negative.”

8. “**PATTERN · NOT A VERDICT.** Open the underlying receipts before drawing conclusions.”

## Composition rules across categories

### The joke may stop the scroll; the literal line must close the ambiguity

Good:

> **HOLE IN THE BAG.**  
> Outcome coverage is missing for 3 of 7 retained launches.

Bad:

> **THIS ONE STINKS.**

The bad version asks the user to infer a verdict the evidence did not state.

### Use evidence-state words as data, not mood

- **OBSERVED** = directly retained from an identified source or observation method.
- **DERIVED** = computed from supported observations under a disclosed method.
- **PATTERN** = recurrence/similarity structure worth inspecting; not intent, identity, skill, or profitability.
- **UNKNOWN** = current evidence does not establish the answer.
- **COMPLETE** = complete only for the explicitly stated supported scope.
- **PARTIAL** = some supported expected scope is covered, some is not.
- **UNVERIFIED** = a claim/value exists but sufficient support is not established.
- **MISSING** = expected evidence/artifact is absent from the retained bundle/source result.

### Prefer specific negation over reassuring implication

Use:

> “No match found in current indexed coverage.”

Not:

> “Looks clean.”

### Capability copy stays boring

When status matters, use the canonical value: **ENGINEERING_PASS**, **DEPLOYED**, **PUBLIC_LIVE**, **BUILDING**, **PLANNED**, **EXPERIMENTAL**, **BLOCKED**.

Do not turn “we built it” into “you can use it” unless deployment/public state supports that.

### One primary action

Social cards, Telegram alerts, and case summaries should have one dominant action. Secondary controls may exist where the interface requires them, but public copy should not read like a menu.

## Pre-publish kill test

Reject the line if any answer is “yes”:

1. Does it sound like generic crypto Twitter?
2. Does the joke hide the literal finding?
3. Does it sound like a corporate AI assistant?
4. Does it imply a stronger claim than the evidence?
5. Could an unsophisticated user mistake a pattern for a verdict?
6. Did a deployer become a creator, or an address become a human?
7. Did recurrence become skill/profitability?
8. Did a missing source become reassuring evidence?
9. Did ENGINEERING_PASS become “live”?
10. Did the copy invent a roadmap date, unrestricted autonomy, or a trading instruction?

If killed, rewrite the literal layer first. Do not add more feral language to rescue it.

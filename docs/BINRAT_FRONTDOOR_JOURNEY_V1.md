## 4. Roadmap readability

Launch-facing roadmap text is not microcopy.

Minimum design targets:

- body explanation: **18px desktop / 17px mobile**;
- important status/kicker: **16px minimum**;
- receipt/evidence/status detail: **14px minimum**;
- primary touch targets: **44×44 CSS px minimum**;
- body measure: roughly **42–50ch**;
- no important customer claim hidden at 11–14px.

At short mobile heights, do **not** shrink body text below the above target just to fit a scene.

Reduce art/spacing first.

## 5. Telegram presentation

The bot should feel like the same Rat as the website.

Use approved mood art:

- idle-neutral — start/home;
- inquisitive — user asks / chooses a dig;
- digging — working;
- evidence-found — supported result;
- repeat-creator — recurrence;
- alert — Watch/Tripwire trigger;
- empty-paws — no supported result;
- error — unavailable/verification failure.

Normal Telegram chat should not lead with internal system labels.

Prefer:

> **FOUND SOMETHING.**

over:

> Intelligence V1 result.

Prefer:

> **PIPE SMELLS WRONG.**

over:

> read plane failure.

The literal line underneath still explains what failed.

## 6. Case hierarchy

A Case begins with:

1. subject;
2. **WHAT THE RAT FOUND**;
3. 2–5 supported facts;
4. coverage / evidence boundary;
5. relevant action;
6. expandable raw receipts.

The first screen should answer “so what?” without requiring the user to understand receipt internals.

Do not hide evidence state. Do hide implementation trivia.

## 7. Failure behavior

- No verified snapshot → **Launches unavailable right now.** Retry.
- Previously verified snapshot goes stale → keep it, show age/stale state.
- Healthy empty result → distinguish from unavailable.
- Sniffer/Tripwire unavailable → explain status; do not render an active employment button.
- Telegram delivery disconnected → show the impairment.
- Unknown evidence → stay UNKNOWN.
- Failed read → never silently preserve a “live” label.

## 8. Visual identity
